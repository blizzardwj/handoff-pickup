# Dispatch a subtask

This session stays in charge of the overall work and hands one subtask to a worker: a subagent, an agent in another CLI or IDE, or a later session. The worker sees only the repository, so the task file is its complete instruction, including how to report back. The worker needs no skill.

## Files

- `docs/dispatch/task-NNN.md`: the task, written by this skill. NNN has three digits, one higher than the highest existing task, starting at `001`.
- `docs/dispatch/task-NNN.result.md`: the report, written by the worker.

## Dispatch

1. Run `git status --short --branch`, `git log --oneline -3`, and `date +%Y-%m-%dT%H:%M%z`. Fill the frontmatter from their output, never from memory.
2. Write the task file from the template in the language the user uses in the conversation. The worker has not seen this conversation: spell everything out, point to `path:line` instead of pasting code, and quote the user's constraints verbatim. Make each acceptance criterion checkable, naming its command where there is one.
3. Tell the user the path and the instruction for the worker: `Read docs/dispatch/task-NNN.md and do what it says.` Start a worker yourself only if the user asked you to and you have a way to do so. Do not commit.

## Collect

When the user asks for the result:

1. Read the task file and its result file. If the result file does not exist, say so and stop.
2. Treat the report as a lead, not a fact. Compare its Changes with `git status --short` and `git diff --stat`, and re-run the acceptance checks that are fast, local, and free.
3. If everything holds, continue with the overall work. If a check fails, the changes do not match, or the worker is blocked, tell the user and wait. Do not edit the task or result file.

## Template

```markdown
---
id: task-003
date: 2026-11-17T16:40-0800
branch: feat/uploader-retry
base_commit: d6923be
---

# Task 003: <the subtask in one sentence>

## Objective
What to produce, and one line on how it serves the overall goal.

## Scope
Files or directories to change. What not to touch.

## Context
Files to read first (path:line). Decisions and constraints that apply, with the user's words quoted verbatim. Approaches already rejected, and why.

## Acceptance criteria
1. ... (and the command that checks it)

## Report
When done, write `docs/dispatch/task-003.result.md`:

    ---
    status: done            # done | partial | blocked
    ---
    ## Outcome        what was done, in a few lines
    ## Acceptance     each criterion: met or not; [verified] with command and result, or [unverified]
    ## Changes        changed files, one line each
    ## Notes          deviations from this task, problems found, questions for the dispatcher

Do not edit this file and do not commit. If something blocks the objective and the code or the web cannot resolve it, set status to blocked, put the question under Notes, and stop.
```
